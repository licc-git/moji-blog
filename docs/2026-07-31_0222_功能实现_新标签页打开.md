## 三、实现原理与关键点

### 3.1 `target="_blank"` + `rel="noopener"`

- `target="_blank"`：浏览器在新标签页打开链接
- `rel="noopener"`：阻止新标签页通过 `window.opener` 访问原页面，避免
  [反向 tabnabbing](https://owasp.org/www-community/attacks/Reverse_Tabnabbing) 风险
- 现代浏览器对 `target="_blank"` 默认隐含 `noopener`，显式写出是为了兼容旧浏览器
  与明确意图。**未加 `noreferrer`**，因为本站是同源跳转，保留 Referer 有助于自身统计

### 3.2 stretched-link 与 target 的兼容性

笔记卡片用 Bootstrap 的 `stretched-link` 让整张卡片可点：

```html
<h3 class="card-title">
  <a href="..." class="stretched-link text-reset text-decoration-none"
     target="_blank" rel="noopener">{{ post.title }}</a>
</h3>
```

- `stretched-link` 通过 `::after` 伪元素覆盖整个 `.post-card` 父容器
- 点击伪元素时，浏览器将该点击派发到对应的 `<a>`，并读取其 `target` 属性
- 因此 `target="_blank"` 对「点击卡片任意空白处」同样生效，**整张卡片都在新标签页打开**

### 3.3 标签 pill 不受影响

卡片底部的标签链接（`tag-pill`）带有 `position: relative; z-index: 2`（见项目约定），
叠在 `stretched-link` 之上，点击标签时：

- 触发的是标签自己的 `<a>`（`href` 指向带 `tag=...` 的筛选 URL）
- **同页跳转**，应用标签筛选
- 不会冒泡到 `stretched-link`，也不会新开标签

这与「标签筛选应替换当前页内容」的交互预期一致，**无需改动**。

## 五、潜在影响与注意事项

1. **多标签页编辑冲突**：用户可能同时打开多个编辑页标签。当前保存逻辑是
   「整篇覆盖式提交」（见 [app/blog/views.py](file:///home/licc/my_blog/app/blog/views.py) 的 `edit`），
   若两个标签都编辑同一篇文章并先后保存，后保存的会覆盖先保存的。
   日常单用户使用风险低，若日后需要可引入乐观锁（`updated_at` 版本号校验）。

2. **浏览器弹窗拦截**：`target="_blank"` 是用户手势触发的同源链接，不会被浏览器拦截。

3. **可访问性**：`target="_blank"` 对屏幕阅读器用户可能造成困惑（无预告地切换标签）。
   若有可访问性要求，可加 `aria-label="在新标签页打开"` 或用 JS 实现「提示后跳转」。
   当前未加，因为新标签打开是本站既定交互约定。

4. **与 `stretched-link` 的 z-index 配合**：未来若在卡片内新增其他可点击元素，
   务必给它加 `position: relative; z-index: 2`，否则会被 `stretched-link` 盖住而不可点
   （与现有标签 pill 的处理方式一致，见 [项目说明 8.1](./2026-07-31_0215_项目说明.md#81-工程约定)）。
